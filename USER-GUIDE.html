Getting started

Any2Odyssey provides continuous desktop capture and controls for Samsung's installed Odyssey 3D conversion engine. Start with Whole desktop and AI input for ordinary desktop content.

1. Connect DisplayPort and the USB upstream cable to your Odyssey G90XF. Install the supported Odyssey 3D Hub and its LeiaSR components; verify Samsung's ordinary 3D playback, then stop its separate conversion player.
2. In Windows display settings, make the Odyssey the primary screen at 3840 × 2160 in landscape orientation.
3. Open Any2Odyssey. Convert automatically when this app opens is enabled on a fresh installation, so it attempts to start after checking prerequisites; the global shortcuts are registered at the same time but are not required. If automatic conversion is disabled, click Turn on 3D.
4. Allow a few seconds for startup. Read the status above the button: Ready is idle, Starting 3D is initialization, and 3D active means the worker reported its output ready. Errors appear here too. A screenshot cannot establish that optical 3D is working.
5. Minimize the controls and use windowed or borderless apps/games. Ctrl+Alt+F10 turns conversion off or on; Quit completely stops conversion and exits.

The installer does not add Any2Odyssey to Windows sign-in startup. Launching the app and starting Windows are separate events.

Use the Source & input, Depth & pop-out and Startup & window behavior sections on the Controls page to adjust conversion. After changing capture, input, depth, pop-out or overlay preferences, click Apply settings / restart conversion. Help stays inside the controls window.

CONTROLS WITHOUT A 3D SETUP
Install-GUI.cmd installs the Windows controls, tray and Help without Hub or a Samsung display. It cannot perform 3D conversion. Automatic conversion still uses the normal prerequisite checks and reports the missing engine/worker; it leaves 3D off. Uncheck Convert automatically when this app opens if you only want to explore the controls. Later, install the supported Samsung setup and run Install.cmd to add full conversion without losing preferences.

DEFAULT LAYOUT
The controls open at 980 × 780 logical pixels. Source and depth settings sit side by side, with startup/window behavior below; all controls fit at the default size and normal display scaling. Narrower windows stack the settings, and shorter windows scroll.

Samsung monitor setup

Capture modes

WHOLE DESKTOP
The recommended mode for games and direct interaction. Captures the primary desktop, including wallpaper, icons and capturable app windows, into a GPU surface outside all physical monitors. The output is excluded from capture to prevent feedback trails; the hardware cursor is excluded to avoid a delayed duplicate pointer.

SELECTED WINDOW
Choose a visible window in Source window. Refresh rebuilds the list. The selected window is fitted to the output, preserving its aspect ratio.

FOLLOW ACTIVE WINDOW
Follows the last eligible foreground window intersecting the primary display. Source window provides the initial selection. Any2Odyssey's own process and the capture worker are excluded from eligible sources.

Selected and active window modes are experimental. Scaling a window does not remap mouse coordinates. Use Whole desktop for aligned mouse interaction.

After changing capture mode or source, click Apply settings / restart conversion. If 3D is off, settings are saved for the next start.

DEFAULTS AND EXAMPLE
Capture defaults to Whole desktop. In that mode, Source window is intentionally disabled because the entire primary display is the source. For a particular app: open the app, choose Selected window, click Refresh, choose its title, and click Apply. Refresh only updates the list; it does not change the capture mode or restart conversion. The window choice is a live handle and is not saved as a durable per-app profile.

DRM-PROTECTED VIDEO
Protected playback on services such as Netflix can block Windows capture, producing black or missing video instead of usable frames. Any2Odyssey cannot convert that protected video to 3D or bypass DRM. Borderless mode does not remove video protection. Ordinary game purchase/launcher DRM is different and does not by itself mean a game is uncapturable.

GAMES AND FULLSCREEN
Exclusive fullscreen is unsupported: it can take exclusive control of the display and prevent the 3D overlay from appearing. Choose Borderless Fullscreen (also called Windowed Fullscreen) or Windowed mode in the game. Borderless fullscreen is recommended for compatible games; support still varies by game, graphics API, overlays and anti-cheat. Any2Odyssey does not bypass capture or anti-cheat restrictions.

Input, depth & pop-out

2D → 3D AUTOMATICALLY (AI)
Use for ordinary desktop content, apps and 2D video. Samsung's engine estimates depth. AI depth can contain artifacts.

SIDE-BY-SIDE INPUT (MANUAL)
Use for a source already containing a left/right stereo pair. Automatic stereo-layout detection is not enabled. The tray's Side-by-side mode and AI conversion mode commands save the choice and restart active conversion.

DEPTH STRENGTH
Range 0.00–2.00; default 0.90. Changes the engine's depth strength. Start at 0.90 and adjust in small steps; stronger depth can make estimation errors more noticeable. The numeric readout is a numeric engine setting, not centimeters or a measured distance.

POP-OUT
Range −1.00–1.00; default 0.00. Adjusts Samsung's pop-out setting, which affects the apparent depth placement relative to the screen. Start at neutral 0.00, change a little, then judge the result at the monitor. These are engine units; the slider does not measure physical protrusion.

APPLY SETTINGS / RESTART CONVERSION
Saves current settings. If conversion is active, it stops the owned worker and starts it again, causing a brief interruption. With conversion off, Apply only saves. Values are stored separately for standard versus side-by-side input in Samsung's overlay settings; Any2Odyssey keeps your selected values in its own preferences.

WHEN CHANGES TAKE EFFECT
Changing the capture mode, the input format, the source window, Keep 3D above apps or a slider updates the page immediately but changes neither the running worker nor the saved value; Unapplied changes appears beside Apply until you click it. Apply saves the values and briefly restarts active conversion; with 3D off, Apply saves them for the next Turn on 3D. Turn on 3D, the tray menu and automatic recovery always use the applied settings. Changes to the automatic-start, recovery or tray checkboxes save those preferences at once but nothing that is waiting for Apply, and they do not change an already running worker.

CHOOSING THE RIGHT INPUT
AI is the default for ordinary images. Side-by-side is for content that already has separate left/right images: it still requires the Samsung/Leia display stack. Any2Odyssey does not automatically recognize stereo layouts or obtain a game's native depth buffer.

Overlay & click-through

The 3D output passes mouse input through to the real desktop or game. Any2Odyssey does not intercept Escape as a stop command. Use Ctrl+Alt+F10 to toggle conversion.

KEEP 3D ABOVE APPS WITHOUT TAKING FOCUS
Keeps output above other applications while preserving their keyboard focus. Click Apply after changing the checkbox. The same toggle in the tray/context menu applies immediately with a brief restart.

RESTORE OVERLAY — CTRL+ALT+F8
Restores output without taking game focus. It requires an active conversion worker. With persistent topmost behavior disabled, use this shortcut if output falls behind another app.

The controls window is separate from the output surface. Moving, resizing, minimizing or hiding these controls does not change projection geometry or click-through behavior. Minimize the controls when playing.

Use Borderless Fullscreen / Windowed Fullscreen or Windowed mode for compatible games. Exclusive fullscreen can prevent the overlay from appearing and is unsupported. Protected video such as Netflix may be black or missing; restore-overlay cannot bypass these restrictions. Windows taskbar auto-hide remains controlled by Windows; other apps' attention requests can keep it visible.

Window, tray & shortcuts

CUSTOM WINDOW CONTROLS
Drag the title bar to move the controls. Drag any border/corner to resize; double-click the title bar or use the square button to maximize/restore. The down-arrow button explicitly minimizes to the tray.

MINIMIZE AND CLOSE TO THE TRAY
Enabled by default. The minus and close buttons hide the controls while conversion keeps running. When unchecked, minus minimizes to the taskbar and close exits the application. Explicit Minimize to tray is available whenever the notification icon exists; without one the button reads Minimize and minimizes to the taskbar.

RESTORE
Double-click the notification-area icon, launch the desktop shortcut again, or press Ctrl+Alt+F9. Windows may place the tray icon in its overflow area.

RIGHT-CLICK
Right-click the tray icon or the controls window for conversion, input mode, overlay recovery, Help, About, Check for updates and Quit commands. The taskbar jump list also includes toggle and show-controls commands.

SHORTCUTS
Ctrl+Alt+F10 — toggle 3D
Ctrl+Alt+F9 — show controls
Ctrl+Alt+F8 — restore output without game focus
F1 — Help while the controls have focus
Alt+F4 — close (honors the tray preference)

Quit completely always stops conversion and exits. Help is an internal page in the same controls window and does not pause the worker. Use Controls to return. The Light / Dark button changes the desktop theme without restarting conversion; its choice is saved separately in ui-settings.json.

RESPONSIVE CONTROLS
Source & input and Depth & pop-out use two columns at the default width and stack when the window is narrower. Startup & window behavior follows beneath them. Resizing changes only the desktop layout, never capture or projection geometry.

Automatic start & recovery

CONVERT AUTOMATICALLY WHEN THIS APP OPENS
Enabled by default. Starts conversion after the controls open and the prerequisite checks pass. This does not add Any2Odyssey to Windows sign-in startup.

RECOVER IF THE CONVERSION PROCESS STOPS
Enabled by default. When a running conversion worker exits unexpectedly, waits 8 seconds and starts it again. Recovery gives up after three failed attempts in a row; the count starts again once conversion has run normally for a minute after a relaunch, or when you start conversion yourself. Turning conversion off cancels recovery. Unchecking recovery during the countdown also cancels that queued retry. Two exits are never retried because a retry cannot help: another renderer already holds the engine, or a prerequisite check failed; the status line names the cause, and the last state the worker reported, so you can fix it and turn 3D on again. Re-enabling recovery does not start conversion; unchecking it leaves an existing worker running.

HOTKEY CONFLICTS
If Ctrl+Alt+F8/F9/F10 cannot all register, the shortcuts stay off for this session; a notice under the status line says so for as long as the controls are open, and companion.log records it (View logs). Automatic start, the buttons, the menus, the tray and --toggle work without the shortcuts. Free the conflicting shortcuts in the other application and reopen Any2Odyssey to get them back.

Your preferences remain in %LOCALAPPDATA%\Any2Odyssey\settings.json. When Any2Odyssey has no settings of its own, including on first launch, it imports the settings of an existing Any2Odd installation if that file exists and can be read; an unreadable Any2Odd file is noted in companion.log and skipped, and because its choices are unknown, automatic conversion and the daily update check then start switched off until you turn them on. The two programs otherwise keep separate files. Changing automatic start, recovery or minimize-to-tray saves the applied preferences. Apply explicitly restarts active conversion for capture, input, depth and overlay changes.

CAMERA/DISPLAY NOT READY AT LAUNCH
A failed prerequisite check leaves conversion off and shows the reason. Recovery is for an exited worker; it is not a background monitor-discovery or hot-plug service. After fixing the camera/display or stopping Samsung's player, click Turn on 3D again.

SAVE BEHAVIOR
Automatic start, recovery and minimize-to-tray changes save immediately. Their enabled state is remembered across upgrades. Keep 3D above apps defaults to enabled and uses Apply to update active conversion. The title-bar Light / Dark button saves only the desktop theme and takes effect immediately without restarting conversion.

Dependencies & architecture

WHAT ANY2ODYSSEY PROVIDES
The desktop GUI, tray menu, settings, shortcuts, capture source, overlay positioning, click-through input handling and worker recovery are Any2Odyssey code, written in Rust. The capture feeds an off-screen surface; the output is excluded from capture to prevent feedback. Rendering stays on this computer; Any2Odyssey does not send captured frames to a hosted conversion service.

SAMSUNG ODYSSEY 3D HUB — REQUIRED FOR WINDOWS 3D
Install Odyssey 3D Hub 1.5.1 with the exact supported ConversionWrapper.dll. Any2Odyssey loads that native library directly for AI depth, stereo conversion and output. It does not include Samsung's engine, AI models or calibration files. Both AI and side-by-side input depend on the installed engine. A Hub update that changes this DLL requires an Any2Odyssey compatibility update.

HUB WINDOW VERSUS RUNTIME
Any2Odyssey's code does not require the Hub's main window to stay open. Samsung/Leia background components and the camera must still be operational; the Hub may be needed to set up or initialize them. Stop the separate Odyssey3DPlayer before starting Any2Odyssey. Closing the Hub window and uninstalling Hub are very different: uninstalling removes required components.

LEIASR AND HARDWARE — REQUIRED FOR WINDOWS 3D
The installed LeiaSR runtime, eye tracking, monitor calibration and the G90XF's optical hardware produce the calibrated glasses-free image. Keep the display's USB upstream connected as well as DisplayPort. The software does not turn an ordinary 2D monitor into a glasses-free display.

WINDOWS — REQUIRED
Windows 11 x64 24H2 (build 26100) or newer is the supported baseline. Any2Odyssey uses Win32 window styles/hotkeys, Windows Graphics Capture, DWM, Direct3D 11 and DXGI through the Rust windows crate. The capture code calls MinUpdateInterval, available from Windows build 26100. These are functional OS dependencies, not just installer restrictions. No .NET runtime or other framework is needed.

GPU AND LIBRARIES
Tested setups are G90XF + NVIDIA RTX 5090 (Any2Odyssey) and G90XF + RTX 4090 (upstream Any2Odd); other GPUs remain unvalidated. The current engine call passes a fixed 16,384-core hint. Install a compatible GPU driver. Any2Odyssey is a single native executable; its Rust dependencies and their licenses are listed in THIRD-PARTY-LICENSES.md. Samsung supplies its own native conversion dependencies. This release has no independent CPU conversion fallback.

INSTALLATION AND BUILD TOOLS
The full Install.cmd installer uses 64-bit Windows PowerShell 5.1 and administrator access to place the worker beside Samsung's engine. It can be installed only for a Windows account that is itself an administrator: approve the elevation prompt with the account you are signed in to. A standard account can install the controls only. Install-GUI.cmd instead installs controls only under your Windows account, without Hub, a Samsung display or elevation; it cannot convert to 3D and never installs a worker. Run the app afterward as your normal user. Source builds use the Rust toolchain (cargo); no Python, Node or Visual Studio IDE is required.

ANY2ODD, ANY2C1 AND PORTALAI
None is a runtime or installation dependency. Any2Odyssey is a reimplementation of Any2Odd; Any2C1 inspired the continuous-conversion workflow; PortalAI is the visual reference for the theme. See Origins & credits for attribution.

Display checks & startup

WHAT IS CHECKED BEFORE CONVERSION
1. Samsung's ConversionWrapper.dll exists at the expected installation path and matches the supported SHA-256 hash.
2. Any2Odyssey's worker executable is installed beside the engine.
3. Windows reports the primary screen as 3840 × 2160.
4. Windows lists a device named 3D Stereo WebCam that is working (no device-manager problem code).
5. Samsung's separate Odyssey3DPlayer process is not running.

WHAT IS NOT DETECTED
Any2Odyssey does not currently read the display's EDID model/manufacturer to positively identify a G90XF, enumerate generic 3D capabilities, select a compatible secondary monitor, or switch primary displays for you. A 4K resolution and a present camera are preliminary checks, not proof that the correct screen, tracking or optical output works.

CONNECTING A SCREEN LATER
Checks run when starting conversion. There is no automatic hot-plug activation service. After connecting the monitor or restoring its USB camera, confirm Windows display settings and click Turn on 3D. If monitor dimensions change during capture, the worker stops and requests a restart. Recovery may retry exited workers, but a failed prerequisite check leaves conversion off.

AUTOMATIC START
Convert automatically when this app opens defaults to enabled. The app registers Ctrl+Alt+F8/F9/F10 as it opens; a conflict is shown in a notice under the status line and recorded in companion.log, and does not prevent automatic conversion. The installer does not register a Windows startup entry. The saved automatic-conversion preference is preserved on upgrade.

READ-ONLY INSTALLER CHECK
install.ps1 -CheckOnly checks full-install package/version/engine compatibility. Add -ControlsOnly for a read-only GUI-install check without requiring Hub. Neither check runs capture, confirms camera tracking, or verifies optical 3D. Check ordinary Samsung playback on the target monitor when diagnosing a display problem.

Windows & Linux

CURRENT DISTRIBUTION
The full Samsung Odyssey converter is Windows x64 only. The Linux build of the same program is a stereo viewer: it opens a side-by-side image and shows it as red/cyan anaglyph or side by side, in a preview and in a separate output window, with the same themed controls and written Help. It can also give an ordinary 2D image depth with an open AI model and render it as a stereo pair. On an Odyssey 3D it can show the picture through Leia's own weaver, with the lens on and the picture following your eyes, by running your own copy of Leia's Windows SR runtime under Wine; with that it can also show a live screen in 3D (both experimental, see below). A second experimental lens output interleaves the pair from numbers you calibrate yourself. From 0.9.0 a release carries the Linux edition too, for x86_64: a package for Arch-based distributions and an archive for others with an installer (install.sh), both with the Wine setup for the Odyssey 3D.

WHY A DIFFERENT INSTALLER IS NOT ENOUGH
The Windows converter relies on Win32 overlay/input styles, Windows Graphics Capture, Direct3D surfaces and Samsung's Windows ConversionWrapper.dll. Samsung's conversion engine does not exist on Linux and is not run under Wine, so depth on Linux comes from an open model and differs from the Windows converter's. Leia's SR runtime (the lens switch, the eye tracker and the weaver) has no public Linux version either; the Linux build uses your own copy of the Windows one under Wine, prepared by contrib/wine-lens/setup.sh, for the lens and the Odyssey 3D output. Nothing of Samsung's or Leia's is distributed with Any2Odyssey.

LINUX SCOPE
On Linux the home page is the stereo viewer. Open a PNG, JPEG or BMP image with Open… (which uses zenity or kdialog), by typing its path and pressing Enter, by dropping the file on the window, or by starting Any2Odyssey with the file as its argument. Choose whether the image is a side-by-side pair, a 2D image to convert to 3D, or a 2D image to show flat; red/cyan anaglyph, side-by-side, Odyssey 3D or lens-interleaved output; the half-width stretch and the eye swap; Save preview PNG… writes the result. Start output opens the result in a window of its own: move it to the display you want, then press F11 or double-click for full screen; Esc leaves full screen and, pressed again, closes the window. Ctrl+Alt+F10 turns the output on and off while the controls have focus. Linux has no global shortcuts, no tray icon, no automatic start and no update check. A second launch hands its request (--show, --quit or a file) to the running instance instead of opening another window. A live screen can be shown in 3D on the Odyssey (see below); a live screen as anaglyph or side by side on another display is not available.

2D → 3D ON LINUX
The input format 2D image → 3D (AI depth) estimates how far away every part of the picture is and renders a left and a right view from it. Depth strength (0.00–2.00) sets how far apart near and far are pushed; Pop-out (−1.00–1.00) sets where the screen plane sits, from everything behind the screen to everything in front of it. Depth detail sets how large the model sees the picture: Standard is the size it was trained at, and Fine, Finer and Finest find thin things and edges better at about twice the time per step (with an NVIDIA GPU all but Finest keep up with a live screen's pictures; on the processor stay with Standard for one). Two things must be installed for it: ONNX Runtime (on Arch: the onnxruntime-cpu package, or onnxruntime-cuda for an NVIDIA GPU) and the depth model, which Any2Odyssey --install-depth-model downloads (about 95 MB, checked against a fixed SHA-256) into the models folder of the data folder. The model is Depth Anything V2 Small, an open model under the Apache-2.0 license; it is not Samsung's and the result will differ from the Windows converter's. The first conversion loads the model and takes a few seconds; the result is a still image; a live screen is a separate input format (below).

ODYSSEY 3D OUTPUT ON LINUX (EXPERIMENTAL)
The output format Odyssey 3D hands the left and right views to Leia's own weaver, the program that makes the glasses-free picture on Windows: it uses the panel's factory lens calibration and the eye positions from Leia's eye tracker, which watches you through the monitor's webcam. Both run from your own copy of Leia's Windows SR runtime under Wine; contrib/wine-lens/setup.sh prepares it from a Windows installation of the Odyssey 3D Hub (see docs/LENS-SWITCH.md for what it needs). Start output then needs no window of its own: the picture opens full screen on the Odyssey 3D, with the lens on. The first start after a login or after the monitor has slept takes up to half a minute. Stop output ends it, and so does Esc while the pointer is on the Odyssey. The line under the output format says how it is going: starting, on and following your eyes, on but not seeing you (the picture is then 2D until it does), or why it failed. Sit 50 to 130 cm from the screen, roughly in front of it.

LIVE SCREEN ON LINUX (EXPERIMENTAL)
The input format Live screen → 3D shows one of your screens on the Odyssey 3D in depth, continuously. It works with the Odyssey 3D output only. Start output and the desktop asks which screen to share (its own dialog; the choice is remembered); pictures of that screen are then given depth by the AI model, rendered as a left and a right view and woven for the lens. On KDE Plasma 6 the screen can be the Odyssey itself, so its own desktop appears in 3D and you keep working on it through the picture: the 3D picture is kept out of the capture and lets clicks through. Untick Draw the pointer into the picture for that, since the real pointer is already there. On other desktops choose a screen other than the Odyssey, which would otherwise show a picture of itself. Choose another screen forgets the remembered choice so that the desktop asks again. Depth strength and Pop-out work as for images and can be changed while it runs, as can Sharpness (sharpens the two views), Depth steadiness (how much of the previous depth is kept, to calm flicker at the cost of following movement more slowly) and Detail (the lines of each eye's view: more are sharper and cost more processor time). The status line shows the pictures and depth maps per second. The picture moves at the screen's own rate; depth follows as fast as the model runs: with an NVIDIA GPU (onnxruntime-cuda) for every picture at Standard depth detail, on the processor around ten times a second. It needs a desktop with the screen-cast portal (KDE Plasma and GNOME have it), on Wayland or X11.

OWN LENS INTERLEAVE ON LINUX (EXPERIMENTAL)
The output format Odyssey lens interleave, own calibration, gives every red, green and blue subpixel of the panel to the left or the right view, the way a lens sheet needs it. It is Any2Odyssey's own two-view interleave, for when Leia's weaver is not set up: there is no eye tracking, so the picture is right for one head position, and it uses no Samsung or Leia software or calibration file. It only separates the views while the Odyssey's lens is switched on; with the lens off it is a picture of fine stripes. The lens is switched by Leia's SR runtime, and its state does not survive a restart from Windows. While lens output is full screen the viewer asks that runtime for the lens through an optional helper program (any2odyssey-lens-helper). There are two: one built against Leia's SDK for Linux, and one that runs your own copy of Leia's Windows SR runtime under Wine, prepared by contrib/wine-lens/setup.sh from a Windows installation of the Odyssey 3D Hub. Without a helper the lens stays off. The line under the lens controls says which. Use it full screen on the Odyssey at 3840 × 2160 with display scaling at 100 %; a scaled or windowed picture does not line up with the lenses.

Three numbers describe the lens sheet: Lens pitch (pixels per lens along a row), Slant (pixels the lenses move sideways per row) and Offset (where the left view starts under a lens, 0–1). They start from rough values and are yours to tune: tick Show the calibration pattern, start the output and make it full screen. The pattern is white for the left eye and black for the right. With the right eye closed the screen should look evenly bright, with the left eye closed evenly dark. Bands across the screen mean the pitch is off (broad bands: nearly right); tilted bands mean the slant is off; the wrong eye being bright means the offset is half a lens out. In the output window the arrow keys change them: Left/Right the offset, Up/Down the pitch, Page Up/Page Down the slant, with Shift for steps a tenth the size, and C switches between the pattern and the image. The numbers are saved in lens.json in the data folder.

Troubleshooting & logs

INSTALLER SAYS INSTALLATION DID NOT COMPLETE
Extract the release ZIP fully. The launcher keeps the precise failure visible in the original console, including failures after elevation. Missing Odyssey Hub blocks full setup. For desktop controls on a PC without a 3D setup, run Install-GUI.cmd; 3D conversion will remain unavailable. For full setup, install the supported Samsung Hub first and run Install.cmd using the same Windows account as the existing installation. Do not bypass an incompatible-engine check.

NO 3D / CAMERA ERROR
Check USB upstream, DisplayPort, the 3D Stereo WebCam in Device Manager, primary-display selection and 3840 × 2160 resolution. Verify Samsung playback first and stop its separate conversion player.

ENGINE MISSING OR CHANGED
Install the supported Odyssey 3D Hub in its default location. Any2Odyssey checks a specific ConversionWrapper.dll hash. A changed engine requires a compatibility update; do not bypass this check.

OUTPUT BEHIND A GAME
Use Ctrl+Alt+F8 and Keep 3D above apps. Exclusive fullscreen is unsupported.

YELLOW CAPTURE OUTLINE
Windows may deny borderless capture access. Capture can continue with its indicator visible; Any2Odyssey does not disable Windows privacy protections.

CAPTURE LIMITS
Protected/DRM video, secure desktops, exclusive fullscreen and apps that stop rendering when occluded may not work. HDR input is normalized to SDR; highlights can clip. Capture and AI conversion add latency, which depends on workload.

VIEW LOGS
Opens %LOCALAPPDATA%\Any2Odyssey. companion.log records application events; worker-status.json and desktop-capture-status.json show available worker/capture diagnostics. Review and redact usernames, window titles and paths before sharing logs. Include Windows build, GPU, Hub version, capture/input mode and reproduction steps in an issue. Optical depth must be checked at the 3D monitor.

About & update check

ABOUT PAGE
The About button in the title bar, About in the right-click menu and About Any2Odyssey in the tray menu open a page with the running version, the commit it was built from, the platform, the executable's folder and what the installer recorded: installation time, install/upgrade/repair, full converter or controls only, and the worker's location. A copy that was not installed says so. The page also carries the credits, the license and links to the project page, releases, changelog and issue tracker.

CHECK FOR UPDATES
Check now asks GitHub for the newest published release and compares it with the running version. The result, the publication date and the release notes appear on the About page; Open release page and Download package open the browser on GitHub. Nothing is downloaded or installed by itself: install an update with Install.cmd from the downloaded package, as described under Install, update & uninstall. Check for updates in the right-click and tray menus runs the same check and opens the page.

AUTOMATIC DAILY CHECK
While Check for updates automatically once a day is on (the default), the controls run one check when they open, at most once every 24 hours. The time of the last successful check is kept in ui-settings.json. Switch the option off on the About page to check manually only. When a newer version is known, the tray icon's tooltip names it.

WHAT IS SENT
A check is one HTTPS request to api.github.com for the latest release of jlobue10/Any2Odyssey, made with Windows' own HTTP client, so the system proxy settings and certificate store apply. The request identifies itself as Any2Odyssey with its version and carries nothing else about the computer. Only pages on GitHub's own hosts are ever opened from a result. From a terminal, Any2Odyssey --check-updates runs the same check and exits with 0 (current), 10 (update available) or 1 (error).

Install, update & uninstall

INSTALLING OR UPDATING
The About page can tell you when a newer release exists (see About & update check); installing it is the manual step described here. Download the Any2Odyssey ZIP from GitHub Releases and extract the entire package to a new folder. Run Install.cmd, or run install.ps1 in 64-bit administrator PowerShell using the same Windows account as the existing installation. Do not uninstall first.

The installer reads the installed version, reports install/upgrade/repair, asks a running Any2Odyssey to quit cleanly, and replaces the application and worker in their existing locations. Settings, logs and Samsung's original overlay-settings backup are preserved. The same version can be reinstalled to repair it; the installer refuses to replace a newer installed version unless you run Install.cmd -AllowDowngrade (or Install-GUI.cmd -AllowDowngrade) from a terminal in the extracted folder, and it likewise refuses to replace a newer conversion worker that another Windows account installed.

Use install.ps1 -CheckOnly for a read-only compatibility/version check. No reboot is required. Full installation requires the supported Samsung engine; it does not patch Samsung binaries.

MIGRATING FROM ANY2ODD
Any2Odyssey does not replace an installed Any2Odd and does not share its files. Whenever Any2Odyssey has no settings file of its own, including on first launch, it imports Any2Odd's conversion preferences if that file exists and can be read. If it cannot be read, nothing is imported and automatic conversion and the daily update check start switched off. Uninstall Any2Odd separately through Windows Installed apps if you no longer want it; both can also stay installed, but run only one at a time because both drive the same Samsung engine.

CONTROLS-ONLY INSTALLATION
Without Hub or a Samsung display, use Install-GUI.cmd (or install.ps1 -ControlsOnly) for the desktop GUI, tray and written Help. It needs no administrator access and appears as Any2Odyssey (controls only) in Installed apps. It installs no worker and provides no 3D conversion. Later, install the supported Samsung setup and run Install.cmd to add full conversion in place, preserving settings. Controls-only setup refuses to replace an installed full worker.

UNINSTALL
Use Any2Odyssey in Windows Installed apps. On a shared PC, quit Any2Odyssey in every signed-in account first; if the conversion worker cannot be removed, the uninstaller shows the reason and removes nothing. Full-mode removal deletes its own files only. Controls-only removal needs no elevation and never deletes anything from Samsung's folders. Uninstalling retains Samsung software, preferences, logs and the original Samsung overlay-settings backup. It does not restore the backup over newer Samsung preferences.
