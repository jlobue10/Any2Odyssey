# Platform support

| Capability | Windows x64 | Linux |
| --- | --- | --- |
| Light/dark controls, Help | Native, custom chrome (egui) | Same chrome and Help; the home page is the stereo viewer |
| Tray / menu | Windows notification icon, jump list | No tray icon yet (planned: StatusNotifier where the desktop supports it); Minimize and Close act normally |
| Ordinary 2D → AI depth | Installed Samsung engine, live on the whole desktop | An open model (Depth Anything V2 Small, Apache-2.0) through the system's ONNX Runtime, then left and right views rendered from the depth map; depth strength and pop-out as on Windows. For still images, and (experimental) for one live screen shown on the Odyssey 3D, with sharpness, depth steadiness and detail controls. Needs `onnxruntime-cpu` or `onnxruntime-cuda` and `any2odyssey --install-depth-model`. The model in the data folder is checked against a fixed SHA-256 before it is loaded, and another file there is refused; a model of your own is named in `$ANY2ODYSSEY_DEPTH_MODEL` |
| Existing SBS input | Samsung/Leia calibrated output | Stereo viewer: an SBS image as red/cyan anaglyph or SBS, half-width stretch, eye swap, preview, output window with full screen, PNG export. Images of up to 16384 pixels a side and 67 million pixels (a side-by-side pair of 8K views fits); larger ones are refused |
| G90XF tracking, calibration and lens output | Samsung/Leia runtime required | Experimental, two ways. (1) "Odyssey 3D": the pair is handed to Leia's own weaver, running with Leia's service and eye tracker from the user's copy of the Windows SR runtime under Wine (`contrib/wine-lens`, `docs/LENS-SWITCH.md`). This needs a Windows installation of the Odyssey 3D Hub that has run this monitor, on a drive Linux can mount: a dual-boot PC is the expected set-up: factory calibration and eye tracking, full screen on the Odyssey. (2) A two-view lens interleave of our own (`core::weave`) with a calibration pattern and three numbers the user tunes (pitch, slant, offset), full screen only, no eye tracking, no use of Samsung's or Leia's calibration files. The lens is asked for while that output is full screen, through an optional helper (`docs/LENS-SWITCH.md`): either Leia's SR runtime for Linux (commercial, not public, untested) or the user's own copy of Leia's Windows runtime under Wine (`contrib/wine-lens`, seen working on a G90XF). Without a helper the lens stays off |
| Whole-desktop source | Windows Graphics Capture | Experimental: one screen, chosen in the desktop's screen-cast portal dialog (PipeWire; Wayland and X11), shown in 3D on the Odyssey. On KDE Plasma 6 it can be the Odyssey's own screen (KWin keeps the 3D picture out of the capture); elsewhere it has to be another screen |
| Selected / follow-active window | DWM thumbnails | Not planned |
| Click-through output | Win32 layered + transparent styles | No: the output is an ordinary window you place and make full screen, except the Odyssey 3D picture of a live screen, which lets clicks through |
| Global shortcuts, automatic start, recovery | Yes | Local shortcuts only (Ctrl+Alt+F10 output, F1 Help, F11/Esc in the output window); output starts manually |
| One instance, `--show` / `--quit` | Named mutex and events | A Unix socket in `$XDG_RUNTIME_DIR`; a second launch hands over its request or file |
| Update check | GitHub Releases, on request or daily | No |
| Installer | Version-aware PowerShell installer | Per release, an Arch Linux package (`packaging/arch/PKGBUILD`, with `any2odyssey-setup`) and an archive with `install.sh` (`packaging/linux/install.sh`); see below |

## What is distributed

- Windows x64: `Any2Odyssey-<version>-windows-x64.zip` with the executable and installer (built by CI on `windows-latest`).
- Linux x86_64, from 0.9.0, two files per release (built by the release workflow, each with a `.sha256`): `any2odyssey-<version>-1-x86_64.pkg.tar.zst` for Arch-based distributions (Arch, CachyOS, EndeavourOS, Manjaro; `sudo pacman -U <file>`), built in an Arch Linux container, and `Any2Odyssey-<version>-linux-x86_64.tar.gz` for others, built on Ubuntu 24.04 (it needs glibc 2.39 or newer and PipeWire; `INSTALL.txt` inside says the rest). The archive has an installer, `install.sh` (`packaging/linux/install.sh`): the program for the user under `~/.local`, then, asking first, the packages it needs (Arch, Debian/Ubuntu and Fedora names; run on CachyOS only), the udev rules, the depth model and the Wine side of the Odyssey 3D; `--uninstall` removes it. For the Wine side it uses a Windows drive it finds by itself only when exactly one is mounted and it is not a removable one (with `--yes`, only when it is plainly a drive inside the machine); Windows on a USB drive, a memory card or a network share, or one of several, is named with `--windows-root DIR`. The package installs the udev rules itself and has the same further steps as `any2odyssey-setup`. After an update the Odyssey 3D step is run again, because the Wine side stays as the earlier version built it until then. Releases later than 0.9.0 also carry build provenance for the three files (`gh attestation verify <file> -R jlobue10/Any2Odyssey`). Both carry the Wine setup for the Odyssey 3D (`wine-lens`; in the package under `/usr/share/any2odyssey/`) and the licenses of what they contain (`THIRD-PARTY-LICENSES.md`, `THIRD-PARTY-LICENSES-LINUX.md`). Neither published file has been installed and run by a person yet: what was run on hardware is a build from the same source. The package can also be built from a checkout:

  ```sh
  git clone https://github.com/jlobue10/Any2Odyssey.git
  cd Any2Odyssey/packaging/arch
  makepkg -si
  ```

  This installs `/usr/bin/any2odyssey`, a desktop entry (it appears as an "Open with" choice for PNG, JPEG and BMP images), the icon, the guide and the license files. `zenity` or `kdialog` provides the Open and Save dialogs; without either, type the path or drop the file on the window. Other distributions: `cargo build --release -p any2odyssey` and run `target/release/Any2Odyssey`.
- Building the Linux edition needs the PipeWire development files and clang (the live capture's bindings are generated from PipeWire's headers); the package depends on `libpipewire`.
- The CI builds and tests the core, the icon tool and the application crate on x86_64 and aarch64 Linux, and builds the Arch package in an Arch Linux container.

## What has been run on Linux

The stereo viewer was built and run on Arch Linux under WSL 2 (x86_64) with the package above: X11 under a virtual display with the Openbox window manager, software OpenGL. Checked there: opening an image by argument and by hand-over from a second launch, the anaglyph preview, the refusal of an odd-width pair, the output window, full screen and Esc, `--show` and `--quit`. The 2D → 3D mode was run there too, on the CPU provider of `onnxruntime-cpu` 1.29 with the downloaded model: a photograph converted to an anaglyph with the expected parallax, and the missing-model message without it. On a CachyOS desktop (x86_64, KDE Wayland, NVIDIA RTX 5090) with a G90XF, the lens switch, Leia's eye tracker, the weaver helper and AI depth on the GPU (`onnxruntime-cuda`) were run as described in `docs/LENS-SWITCH.md`. On the same machine the Odyssey 3D output was seen from the viewer on the panel: a still image with AI depth (upright, depth the right way round, following the viewer), and the live screen with the Odyssey's own desktop as the screen on KDE Plasma 6.8, including video playing. Known there: the desktop's real pointer, drawn flat over the 3D picture, looked doubled through the lens early in that session and looked right by its end, after the eye tracking's timing had been corrected (nothing was changed for the pointer itself); some flicker while the head moves remained after the camera's time stamps were corrected (which reduced it); the repeated stop and start and the 2160-line detail were fixed afterwards and checked by measurement only. **Not yet run:** the rest of the viewer on a physical Linux desktop, the zenity/kdialog dialogs, drag and drop, more than one display, and aarch64 beyond CI's build and tests.

The viewer was also run under a Wayland compositor without a screen (sway 1.12 with two headless outputs, software OpenGL, in the same WSL 2 installation; start-up on weston 15 as well). Checked there: it starts as a Wayland client whenever `WAYLAND_DISPLAY` names a compositor, with or without XWayland beside it, and under XWayland alone as an X11 client; the compositor reports the application id `any2odyssey` (the desktop entry's name, so the desktop finds the icon and groups the windows) for the controls and the output window; the picture is sharp at output scales 1.5 and 2; the output window goes full screen on the output it is on, comes back to the other output when its own is unplugged, and leaves full screen with F11, a double click or Esc; 200 hand-overs (`--show`, `--toggle`, `--open`) arrive while the controls are on another workspace; zenity opens as a Wayland window; when the compositor dies the program exits 1 at once. A live screen without a session bus, or with a portal that has no screen cast, ends with the reason on the page. What Wayland does not let a window do: `--show` cannot raise or restore the controls (they ask for attention instead, which the desktop shows in its task bar), a window cannot place itself on a display (the output window is moved there by hand, as its hint says, or by a window rule of the desktop), and a window icon comes from the desktop entry only. On a compositor without server-side decorations (GNOME) the output window has no title bar: move it with the desktop's own shortcut (Super + drag). **Not run under Wayland:** KDE Plasma itself (window rules, the task bar's attention mark, KWin's handling of a minimized window), drag and drop, a hardware GPU, and anything of the Odyssey 3D output, whose window belongs to Wine.

## Why Samsung's engine cannot be used on Linux

Conversion is done by Samsung's `ConversionWrapper.dll` (CUDA/ONNX, Windows x64) and the calibrated glasses-free output needs the LeiaSR runtime, eye tracking from the monitor's camera and the lens calibration. The conversion engine does not exist for Linux, and Leia's SR runtime for Linux is a commercial package that is not public. Running Samsung's conversion engine under Wine/Proton is unvalidated and outside this project's scope. Leia's runtime is asked to switch the lens on, either by its Linux package where that is installed or by its Windows service running under Wine (`docs/LENS-SWITCH.md`); its eye tracker and weaver run under Wine as well, from the user's own copy, and the viewer's Odyssey 3D output uses them. Any2Odyssey's Linux edition is therefore the stereo viewer described above, with depth from an open model.

## Development machines

The maintainer develops on an aarch64 Linux laptop (cross-checks the Windows code with `cargo check --target x86_64-pc-windows-msvc`) and tests the Windows converter on an x64 Windows PC with a G90XF. Hardware results are recorded in `CHANGELOG.md` and `docs/TESTING.md`.
