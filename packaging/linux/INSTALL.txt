Any2Odyssey for Linux (x86_64)
==============================

This archive holds the Linux edition: a stereo viewer that shows side-by-side images as red/cyan anaglyph or
side by side and, on a Samsung Odyssey 3D (G90XF), glasses-free through Leia's own weaver, for images and for
a live screen. README.md and USER-GUIDE.html describe it; docs/PLATFORMS.md says what has been tested.

Arch-based distributions (Arch, CachyOS, EndeavourOS, Manjaro) should prefer the package attached to the same
release (any2odyssey-<version>-1-x86_64.pkg.tar.zst, installed with `sudo pacman -U <file>`).

Installing it
-------------

    ./install.sh

installs the program for your user (under ~/.local) and then asks about each further step: the packages it
needs, the udev rules for the Odyssey 3D, the depth model, and the Wine side of the Odyssey 3D (from a mounted
Windows drive that has the Odyssey 3D Hub). Steps that need root say so and use sudo for that step only. Run it as
yourself, not with sudo: started as root it refuses to install into a folder that is not root's alone.
`./install.sh --help` lists the options (--yes, --dry-run, --windows-root DIR, --uninstall and others). It
knows the package names of the Arch, Debian/Ubuntu and Fedora families; it has been run on CachyOS and,
without an Odyssey 3D, on Ubuntu 24.04. A package that your release does not have is named and left out.

To remove it again, run the copy of the installer that the installation keeps; the installer prints the
command when it finishes (`~/.local/share/any2odyssey/install.sh --uninstall`, or the same under the folder
given with --prefix). From this archive, `./install.sh --uninstall` removes the installation under ~/.local,
and one made with `--prefix DIR` when given the same `--prefix DIR`.

The installer uses a Windows drive it finds by itself only when exactly one is mounted and it is not a
removable one; a drive it cannot place (a network share) it asks about with a warning, and does not use
with --yes. For Windows on a USB drive, a memory card or a network share, or when several drives have
one, name it: `./install.sh --windows-root /path/to/that/drive`.

When you update Any2Odyssey, run `./install.sh` from the new archive and let it prepare the Odyssey 3D
again: the Wine side stays as the earlier version built it until then.

It was built on Ubuntu 24.04 and needs a system at least that new (glibc 2.39). To try it without
installing, run `./any2odyssey` here.

What the installer sets up, if you would rather do it by hand
--------------------------------------------------------------

- The program: `any2odyssey` to ~/.local/bin, `any2odyssey.desktop` to ~/.local/share/applications,
  `any2odyssey.png` to ~/.local/share/icons/hicolor/256x256/apps. It needs PipeWire (libpipewire-0.3),
  libxkbcommon (in an X11 session libxkbcommon-x11 as well: Debian and Ubuntu call it libxkbcommon-x11-0),
  OpenGL (libglvnd / Mesa or the NVIDIA driver), and Wayland or X11 client libraries.

- 2D to 3D (AI depth): your distribution's ONNX Runtime, 1.22 or newer, under the name libonnxruntime.so
  (Arch: onnxruntime-cpu, or onnxruntime-cuda with cudnn for an NVIDIA GPU; Debian and Ubuntu:
  libonnxruntime-dev; Fedora: onnxruntime-devel), then `./any2odyssey --install-depth-model` (needs curl;
  downloads the open depth model, about 95 MB). Not every release has one: Ubuntu 24.04 has no ONNX
  Runtime package, and the 1.21 of Debian 13 and Ubuntu 25.04 and 25.10 is older than the program accepts
  (Ubuntu 26.04 has 1.23, Fedora 45 has 1.26). There this mode needs a libonnxruntime.so from elsewhere,
  named in the environment variable ORT_DYLIB_PATH; everything else works without it.
  The model in your data folder is checked against a fixed SHA-256, at the download and again before the
  program loads it; to use another model, give its path in the environment variable
  ANY2ODYSSEY_DEPTH_MODEL.
- Open and Save dialogs: zenity or kdialog.
- A live screen: a desktop with the screen-cast portal (KDE Plasma and GNOME have it).
- The Odyssey 3D's lens, eye tracker and weaver: these are Leia's, and they come from a Windows
  installation of yours. The expected set-up is a DUAL-BOOT PC: Windows with the Odyssey 3D Hub on a drive
  of this machine, which has shown 3D on this monitor at least once (that is when it stores the monitor's
  calibration). Mount that Windows partition read-only (file manager, or
  `udisksctl mount -b /dev/<partition> -o ro`; `lsblk -f` lists the partitions). A BitLocker-encrypted
  partition must be unlocked or have BitLocker suspended first. The drive is needed only during set-up:
  about 1 GB is copied to your data folder. Without a Windows installation this part is not available;
  everything else works.
  Also needed: Wine, mingw-w64-gcc, clang, a C compiler, Python 3, xrandr and rsync (Debian and Ubuntu:
  wine gcc-mingw-w64-x86-64 clang gcc python3 x11-xserver-utils rsync; Fedora: wine mingw64-gcc clang gcc
  python3 xrandr rsync). Then, as docs/LENS-SWITCH.md explains:

      sudo cp wine-lens/70-any2odyssey-lens.rules /etc/udev/rules.d/
      sudo udevadm control --reload && sudo udevadm trigger
      wine-lens/setup.sh /path/to/mounted/windows-drive

  Nothing of Leia's or Samsung's is in this archive: the setup copies your own installation.
